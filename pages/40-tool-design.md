# Part 4. 도구와 연동

## 40. 도구 설계

도구가 좋아야 에이전트가 일을 합니다. 도구 설계가 에이전트 품질의 절반입니다.

좋은 도구의 조건입니다. 첫째, 하나의 도구는 하나의 일을 합니다. "검색하고 요약하고 저장하는" 도구는 나쁩니다. 검색, 요약, 저장을 나누세요. 둘째, 이름과 설명이 명확합니다. 에이전트는 설명을 보고 도구를 고릅니다. "언제 쓰는지"를 적습니다. 셋째, 입력 형식이 단순합니다. 필요한 것만 받습니다. 선택 사항은 줄입니다. 넷째, 에러 메시지가 친절합니다. 실패 이유와 다음 행동을 알려줍니다.

도구의 수를 정하는 것도 설계입니다. 너무 많으면 에이전트가 헷갈립니다. 10개를 넘기면 정리를 고려하세요. 비슷한 도구들을 묶거나, 단계별로 나눠서 줍니다.

도구와 직접 코드의 구분입니다. 정해진 순서로 할 수 있는 것은 도구로 만들지 말고 코드로 씁니다. 에이전트에게 판단이 필요한 것만 도구로 줍니다. 이것이 비용과 품질을 모두 잡는 길입니다.

실습: 도구 설명 다듬기
1. 만든 도구의 설명을 읽기
2. "언제 쓰는지"가 적혀 있는지 확인하기
3. 입력 항목을 줄일 수 있는지 보기

핵심 정리
- 하나의 도구는 하나의 일을 하고, 설명에 "언제 쓰는지"를 적는다.
- 입력은 단순하게, 에러 메시지는 친절하게 만든다.
- 도구는 10개 이하로 유지하고, 정해진 순서는 코드로 쓴다.
