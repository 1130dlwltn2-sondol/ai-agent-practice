# 21. 라우팅

라우팅은 입력을 보고 처리 경로를 고르는 패턴입니다. 분류기가 먼저 입력의 종류를 판단하고, 종류별로 다른 처리를 합니다.

예를 들어 보겠습니다. 고객 문의가 오면 먼저 종류를 봅니다. 환불 문의는 환불 절차로, 배송 문의는 배송 조회로, 기술 문의는 기술 지원으로 보냅니다. 각 경로는 그 종류에 특화된 프롬프트나 워크플로우를 씁니다.

이 패턴이 좋은 경우입니다. 입력의 종류가 명확히 나뉠 때입니다. 종류별로 최적의 처리가 다를 때입니다. 하나의 프롬프트로 다 처리하기 어려울 때입니다.

설계 요령입니다. 분류 기준을 명확히 합니다. 종류가 너무 많으면 분류기가 헷갈립니다. 5개 이하가 적당합니다. 분류에 실패했을 때의 기본 경로를 정합니다. 확신이 낮으면 사람에게 넘기는 식입니다. 분류 결과를 로그로 남겨 나중에 기준을 다듬습니다.

실습: 문의 분류기
1. 문의 종류 4개를 정하기
2. 분류 프롬프트 만들기
3. 종류별 처리 프롬프트 만들기
4. 실제 문의로 테스트하기

핵심 정리
- 입력을 분류해 종류별 경로로 보낸다.
- 종류는 5개 이하로, 실패 시 기본 경로를 둔다.
- 분류 결과를 로그로 남겨 기준을 다듬는다.
